# Demo note M1: XML model and tree editor

This note shows the result of milestone M1. FastTick opens BT.CPP 4 XML
files, keeps all text that it does not change, and edits the trees.

![Edit mode](images/edit.png)

## What M1 gives

- A lossless XML model. When FastTick saves a file that it did not change,
  the file stays the same, byte for byte. A change touches only the changed
  elements and attributes.
- The BT layer: trees, nodes, ports, pre-conditions and post-conditions,
  SubTree remapping, node models and the built-in models of BT.CPP 4.9.0.
- Projects with one or more XML files (`.ftproj`). The project file also
  keeps the layout state and the unconnected nodes.
- Validation with the rules of BT.CPP. The problems show on the canvas and
  in the problems list.
- The tree editor in the GUI:
  - Tree list (trees grouped by file), tabs and split view.
  - Canvas: add, delete, move, connect, disconnect and reorder nodes.
    Multi-select, copy, cut, paste and duplicate. Zoom, pan, fit to view,
    automatic layout from top to bottom or from left to right.
  - Palette: the node types by kind, with a search field. A drag onto the
    canvas adds a node. The model dialog adds and changes node models.
  - Inspector: name, type, ports (a literal value or a `{key}`), the port
    type and the "required" mark, `_autoremap`, pre-conditions and
    post-conditions, and the problems of the node.
  - SubTrees: create a SubTree from the selected nodes, open the referenced
    tree, edit the remapping, and show a SubTree inline (read-only).
  - Problems list, XML panel (read-only, synchronized with the selection)
    and search.
  - Undo and redo. Keystrokes in one field become one undo step.
  - Save, save as, new file, recent files, keyboard shortcuts with a help
    dialog, light and dark themes.

## Try it

1. Build FastTick: `cargo build --release`.
2. Run `target/release/fasttick test_harness/trees/main.xml`.
3. Drag the node `say_default` to the right end of the node `say_text`.
   The node moves after `say_text`.
4. Push Ctrl+Z. The node goes back to its old position.
5. Right-click the node `fallback`. Select **Add child** > **Actions** >
   **AlwaysSuccess**. The new node is the last child of `fallback`.
6. Select the node `say_text`. In the inspector, change the value of the
   port `message`. The card and the XML panel show the new value.
7. Right-click `fallback`. Select **Create SubTree from selection…**. Type
   the ID `Checks` and click **Create**. The tree list shows the new tree.
8. Push Ctrl+F and type `count`. The search panel lists the matches, and
   the canvas marks the nodes.
9. Push Ctrl+S to save the file. (Use a copy of the file for this test.)

## Evidence

- `cargo test -p fasttick-core`: 389 tests. They include round-trip tests
  of 317 XML texts from the BT.CPP repository, property tests of the XML
  model and of the layout, and a comparison of the validator with BT.CPP
  4.9.0 itself.
- `cargo test -p fasttick-app --test ui_edit`: 15 headless UI tests of the
  authoring flows (drag and drop, context menu, inspector, palette, model
  dialog, problems, XML panel, search, tree list, projects with several
  files).
- `cargo test --release -p fasttick-app --test edit_perf -- --nocapture`:
  with 5,000 nodes, one keystroke in the inspector takes about 14 ms (edit,
  validation, new canvas tree and the next frame).

## Limits

- The XML panel is read-only. Edit the tree on the canvas or in the
  inspector.
- The editor does not convert BT.CPP v3 files to v4.
